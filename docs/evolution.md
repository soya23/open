# なぜ zellij を捨てたか — 破壊の系譜

多重化ツールは、前世代の「暗黙の前提」を壊して価値を生んできた。

## 系譜

**screen / tmux (〜2007)** が壊したもの: 「端末は接続と運命共同体」。
セッションの永続化で SSH 切断から作業を守った。
残した前提: 環境は玄人が設定ファイルで組み立てるもの。

**zellij (2021)** が壊したもの: その「自分で組み立てろ」。
箱から出してすぐ使え、画面下に今押せるキーが常時表示され(discoverability)、
レイアウトは KDL で宣言的に共有できる。tmux の暗記文化を不要にした。
残した前提: **ペインの中身は人間がキーを打つ生のターミナルである**。

**zeliji (いま)** が壊すもの: その「ペイン = 端末」。

## エージェント時代にこの前提が壊れる理由

Claude Code のようなエージェントを並列に走らせるとき、生の TTY 出力は
ほぼノイズだ。人間が本当に見たいのは:

- 誰が動いていて、誰が入力待ちか (zellij-attention 等の監視プラグインが
  一大カテゴリ化したのは、zellij 単体でこれが見えない証拠)
- 各エージェントが今どのツールを叩き、何をコミットしたか
- タスクボードの進行と、役割間の連絡

つまり必要なのは端末の多重化ではなく **状態の多重化**。
claude は `--output-format stream-json` で構造化イベントを吐ける。
ならば端末エミュレーション(VT100 パース、スクロールバック、リサイズ…
zellij の重さの根源)は丸ごと不要になる。

## 新しい形: cockpit

`zeliji up` は zellij を起動しない。自前の cockpit (curses、標準
ライブラリのみ) を開き、役割ごとのカラムに **構造化イベントの
タイムライン** を流す:

```
┌ backend ● RUN ──────────┬ frontend ○ WAIT ! ─────┐
│ ⚒ Bash zeliji task claim 1│ ✔ done: cli.py 実装済み │
│ ⚒ Write server/greeting.py│   (指示待ち)            │
│ ✎ commit b8bae6a          │                        │
├───────────────────────────┴────────────────────────┤
│ Tasks: 1 todo · 1 doing · 2 done   msg: backend→…  │
│ Tab focus · Enter instruct · g nudge · q quit      │
└────────────────────────────────────────────────────┘
```

- ペインへの「入力」はキーストロークではなく **指示** (Enter で
  フォーカス中のエージェントに次の指示を送る = `--resume` で同一
  セッション継続)
- 入力待ちになった役割は `!` でハイライト (attention 機能の内蔵)
- 画面下は常時キーヒント (zellij から奪った discoverability)

## zellij から奪ったもの / 捨てたもの

| 奪った | 捨てた |
|---|---|
| 分割表示の見易さ | 端末エミュレーション (最大の重さ) |
| キーヒント常時表示 | キーバインドの横取り (通常キーのみ使用) |
| 宣言的設定 (zeliji.toml) | プラグインシステム (ボードは只のファイル) |
| 箱から出してすぐ | 常駐サーバプロセス |

レガシーブリッジとして `zeliji up --zellij` は残す (従来どおり
KDL レイアウトを生成して zellij で生ターミナルを開く)。
生の対話セッションをどうしても触りたい時はそちら。

## 次に壊されるとしたら

zeliji の前提は「人間が cockpit を見ている」。エージェントの信頼度が
上がれば、見ること自体が不要になり、通知とレビューだけが残るはず。
その日が来たら cockpit も捨てる。
